# C-性能专项-1（文档行 15913–25000）

> 本轮：用户要求专门针对「性能与卡顿」做深入检查。AI 启动 2 个性能专项智能体（Agent A 渲染/计算；Agent B 网络/主线程/内存/加载），并尝试用 mcp-chrome 做运行时性能 trace。
> 本区间内容以两个 agent 的文件读取 + 逐文件性能反模式标注为主；两个 agent 的最终报告在 47660 行之后（不在本区间）。

## 结论/背景

- **[结论]** 运行环境 — vite dev server 已不可用（`curl http://127.0.0.1:5173/` 返回 `000`，`ps aux | grep vite` 计数 0）→ 无法做 mcp-chrome 运行时性能 trace | 本轮只能产出静态性能审查结论
- **[结论]** 策略 — AI 判断 playwright 已因 chromium sandbox（root 环境）失败，mcp-chrome 很可能同样失败；因此改为「2 个智能体静态深挖 + 尝试运行时 trace」双轨 | 运行时数据缺失风险
- **[架构]** Agent 分工 — Agent A 覆盖 routes/_layout/ 全部 15 个页面 + components/Douyin/ 全部 12 个组件 + Sidebar/Main.tsx、Navigation/HorizontalNavigation.tsx、Common/DataTable.tsx、Common/PageShell.tsx | 渲染/计算专项
- **[架构]** Agent 分工 — Agent B 覆盖 routes/_layout/、components/Douyin/、components/Common/(DataTable/ViewModeToggle/QueryErrorState)、hooks/、utils.ts、main.tsx、vite.config.ts | 网络/主线程/内存/加载专项
- **[结论]** Agent A 的 10 类反模式清单（审计口径） — ①未 memo 的派生计算 ②每次 render 重建对象/数组/Map/Set ③useEffect 依赖不稳定 ④useRouterState/useSearch 无 select ⑤每行挂载重组件或 useQuery 实例 ⑥key 不稳定 ⑦selected 用数组 + includes（O(n)） ⑧内联对象/数组作 prop（含 queryKey 新引用） ⑨大组件无拆分（1000+ 行/20+ useState） ⑩多 query 轮询频率叠加
- **[结论]** Agent B 的 12 类反模式清单（审计口径） — ①高频轮询无暂停（无 `refetchIntervalInBackground:false`、终态不停） ②搜索无防抖 ③串行 await 循环 ④前端全量加载（do-while 分页拉全量） ⑤主线程拼巨大字符串/JSON.stringify 比对象 ⑥无上限并发 ⑦内存泄漏（setTimeout/objectURL/AbortController） ⑧图片无 width/height 致 CLS ⑨iframe 重挂载 ⑩大列表无虚拟滚动 ⑪无 staleTime ⑫bundle 体积（大依赖未 code split）
- **[结论]** 分析范围文件清单（实际存在） — routes/_layout/ 下 admin、developer-tools、douyin-accounts、douyin-browsers、douyin-comments、douyin-creators、douyin-interactions、douyin-keywords、douyin-library(.feed)、douyin-request-logs、douyin-tags、douyin-tracks、douyin-tracks_.$trackId、douyin、douyin_.$taskId(.feed)、index、items、settings；components/Douyin/ 下 24 个文件；components/Common/ 下 11 个；components/Sidebar/ 3 个；components/Navigation/ 4 个

## 二、横切关注（C1–C11，系统性问题）

- **[架构]** C1 表单模式分裂 — `react-hook-form` + `zod` 已安装且 `login` 在用，但 `CreateTaskDialog`、`InteractionComposerDialog`、`BatchCommentDialog`、tracks/keywords 创建表单全部手写 `useState`，校验散落在 submit 内、无 `onBlur` 实时反馈、重置不完整 | 涉及 6+ 核心表单 | 严重度：高
- **[性能]** C2 轮询策略不一 — 轮询间隔 1s/2s/3s/5s/10s 混用；多数 query 未加 `refetchIntervalInBackground:false`；任务进入终态后仍在轮询（`InteractionLiveMonitor` 1s 永不停）| 涉及 15+ query | 严重度：高

- **[架构]** C4 错误处理分裂 — `handleError.bind(showErrorToast)` vs `handleError.call(showErrorToast, error as ApiError)` vs `error as never` 三种风格；`error as ApiError` 对非 ApiError 不安全 | 涉及全站 mutation | 严重度：中
- **[架构]** C5 重复代码 — `formatDate`/`formatUnix`/`compact` 6+ 处、`Pager` 2 份、`crawlTypeLabels` 2 份、`browserApiBase` 2 份、`taskLabel` 2 份、`parseKeywords`/`parseCreatorTargets` 重复 | 涉及全站 | 严重度：中
- **[风格]** C6 CSS 变量 vs 原生色混用 — `MetricCard`/`StatusPill`/`CreatorAvatar`/`InteractionLiveMonitor`/`AuthLayout` 渐变/`TaskExecutionProgress`/feed `bg-[#050507]` | 涉及 10+ 组件 | 严重度：中
- **[架构]** C7 localStorage 散落 — `useAuth`/`ViewModeToggle`/`theme-provider`/`VideoPreviewDialog`/feed，key 硬编码；`ViewModeToggle` 无 try-catch（隐私模式崩溃）| 涉及 5+ 处 | 严重度：中
- **[安全]** C8 手动 fetch + token 绕过 client — 二维码、视频预览、导出、媒体下载等直接用 `localStorage.getItem("access_token")` + 原生 `fetch` | 涉及 6+ 处 | 严重度：中

- **[i18n]** C10 i18n 缺失 — 全站中文硬编码无框架；`DataTable` 英文混用（"No results found"/"Showing… entries"/"Rows per page"）| 涉及全站 | 严重度：中

## 七、总结论

- **[结论]** 前端功能完整度高，但存在 3 个「一行即可修」的严重 bug（H1 / H2 / H9）
- **[结论]** 鉴权安全基石薄弱（H4–H8）—— token 明文存储、不校验有效性、登录后不刷新用户、登出不清理缓存、工具页无权限控制
- **[结论]** 横切一致性债务较重（11 项系统性问题），是「多风格 / 换肤」目标的主要阻碍
- **[结论]** 建议修复节奏：先清高严重度的「快赢」项（H1/H2/H9）→ 再按横切关注做批量收敛（轮询 / 表单 / 确认对话框 / 重复代码各一轮）→ 最后推进 token 化以支持多风格目标

## 明确不做（需后端 / 已否决 / 风险过高）

> **本次执行中新发现的阻断项**（报告未指出，实测后端接口得出）：

| 项 | 原因 |
|---|---|
| **O20 为「任务 / 互动 / 账号 / 日志」补服务端排序** | 经查 OpenAPI 生成类型：`DouyinListRequestLogsData`、`UsersReadUsersData`、`ItemsReadItemsData` **都只有 `limit`/`skip`，没有排序参数**。报告说「请求日志有服务端排序但前端无 UI」**不准确**。补排序必须后端先加 `sortBy`/`sortOrder`。有排序参数的三个列表（tags / creators / library）本就有排序入口，其中 tags 本次已改为表头点击排序。 |

### 本轮修正的一处类型设计缺陷

`FilterChip` 初版只接受 `false | null | undefined`，但业务惯用写法 `someFilter && {...}` 在 `someFilter` 为字符串时会产出 `""`、为 `boolean` 变量时产出 `boolean`，导致两处类型错误。已改为**按结构过滤**（是不是带 `key/label/value` 的对象），而非按真假值。

1. **`row-highlight` 用在卡片上有视觉回归** —— 该动画以「底色渐隐到透明」收尾（为 `<tr>` 设计），卡片自身有 `bg-card` 底色，套用会让卡片渐变成透明。已限定只用于表格行。
2. **`FilterChip` 类型过窄** —— 初版只接受 `false | null | undefined`，但业务惯用写法 `someFilter && {...}` 在 `someFilter` 为字符串时会产出 `""`。已改为按结构过滤。
3. **`useVirtualRows` 的 JSDoc 写错 API** —— `@tanstack/react-virtual` v3 暴露的是方法 `getVirtualItems()` / `getTotalSize()`，不是属性。我按属性写文档，误导 agent 写出 `virtualizer.virtualItems`，一次性引入 13 个类型错误。已把 hook 改为返回解包后的普通字段。
4. **`validateSearch` 返回类型必须是可选属性** —— 写成 `{ track: string | undefined }` 时属性是**必填**的，会让 TanStack Router 要求所有指向该路由的 `<Link>` 都传 `search`。已全部改为 `{ track?: string }`。
5. **`RowContextMenu` 初版用 `<div>` 包菜单项** —— 正是报告 H16 警告的「破坏 Radix 方向键导航」的写法。已改用 `Fragment`。

## 追加 · A1 列可见性覆盖到全部手写表格

> 用户反馈：「表格字段太多，想自己勾选只显示其中几列，页面上没有这个入口。」
> 此前该能力只挂在 `DataTable` 上（只有 `admin` / `items` 两个页面自动获得），
> 其余列表全是手写 `<Table>`，用户看不到入口。本次补齐。

**新增零件**：
- `src/hooks/useTableColumns.ts` —— 手写表格的列可见性。**存「被隐藏的列」而不是「可见的列」**，这样以后给表格加新列时新列默认可见，不会被旧偏好意外藏起来。列被删掉时旧 key 会自动清理。
- `src/components/Common/TableColumnMenu.tsx` —— 列显示/隐藏菜单（勾选后不关闭菜单，方便连续调整；菜单项用 `DropdownMenuItem` 直接作子元素，不套 `div`）。

**接入页面（12 个）**：任务管理、视频资源库、评论管理、请求日志、标签管理、关键词管理、互动任务、赛道列表、账号池、赛道详情（关键词表）、作品面板、媒体任务管理。加上原有的 `admin` / `items`，**全部 14 个表格都有列设置入口**。

**接入时统一处理的三个坑**（否则会列错位）：
1. 表头与**每一行**的单元格都要各自包 `isVisible`，且要覆盖加载态 / 空态 / 展开行等全部分支
2. 空态 / 加载态 / 表尾的 `colSpan` 从写死数字改成按可见列数计算
3. 只有 table 视图接入，cards / rows 不是表格

设计上的两个取舍：
- **操作列一律 `alwaysVisible`** —— 藏掉它用户就没法操作了，所以不进菜单。
- **`defaultHidden` 用得克制** —— 只有确实次要的长 ID 列（如任务管理的「任务 ID」）才默认隐藏；其余保持默认全可见，避免用户升级后发现列「消失」了。

# 前端信息架构与视觉密度优化方案

> 评估日期：2026-08-18 ｜ 视角：终端用户的实际操作体验
> 方法：以"用户要完成一件事"为主线走查全部业务页面，结合代码级事实（文件行号佐证）
> 核心结论：当前前端是**"功能完备的管理后台"，但还不是"引导用户干活的工作台"**——所有信息平铺在用户面前，用户需要自己从中找出"现在该看什么、该做什么"。

---

## 一、问题诊断（用户视角）

### 1.1 入口问题：用户"从哪开始"是不明确的

创建采集任务这件**最核心的事**，系统里有四个入口，且行为不一致：

| 入口 | 位置 | 提交后的行为 |
|------|------|-------------|
| 任务列表"创建任务" | `CreateTaskDialog.tsx` | 跳转到任务详情 ✅ |
| 赛道卡片"运营这个赛道" | `douyin-tracks.tsx` TrackWorkspaceDialog | 仅 toast，不跳转、不刷新任务列表 |
| 关键词页"批量建任务" | `douyin-keywords.tsx` BatchTaskDialog | 仅 toast，不跳转、不刷新任务列表 |
| 作品行"追爬作者/重爬评论" | `AwemeActions.tsx` | 跳转到新任务详情 ✅ |

用户的真实困惑：
- **"我要开始采集，应该去赛道、关键词还是任务页？"**——三个页面都能发起，没有唯一权威入口，新手需要在三个页面之间来回理解它们的关系。
- 赛道页被用户感知为"总入口"，但赛道页本身承载了过多职责：赛道 CRUD、关键词选择与移动、任务组织、账号选择、启动采集——`douyin-tracks.tsx` 单文件 1284 行，弹窗套弹窗（工作区弹窗 549-1073 行）。
- 两个批量入口建完任务后**连任务列表查询都不失效**（`douyin-keywords.tsx:606-848`、`douyin-tracks.tsx:630-666`），用户切到任务页看到的是旧数据，"任务到底建了没有"的第一反应无法被回答。

### 1.2 状态前置问题：创建时"这个词爬过没有"是盲区

这是用户点名的问题，代码事实如下：

**数据其实是有的。** 关键词表格已经有"获取状态"列（`KeywordStatusBadge`）、"关联任务"列（N 个任务 + 成功/失败/进行中计数）、"来源作品"数、"最近获取"时间（`douyin-keywords.tsx:394-400` 表头、438-452 行渲染）。

**但在用户最需要它的时刻——创建的那一刻——这些信息全部缺席：**

1. **创建任务时**：`CreateTaskDialog` 的目标输入是一个**纯文本域**（`CreateTaskDialog.tsx:341-346`，placeholder"每行一个关键词，例如：FastAPI"）。用户凭记忆打字，系统不提供任何"这个词已存在 / 上次爬取于 X 天前 / 已有 N 个作品"的提示。textarea 和自由文本意味着系统和关键词库是**断开的**——用户在关键词页精心维护的词库，在创建任务时完全用不上。
2. **创建关键词时**：`CreateKeywordsDialog` 也是批量文本输入，**提交之后**才在 toast 里告诉你"新增 X 个，已存在 Y 个"（`douyin-keywords.tsx:527`）。重复检查是事后的，用户无法边输入边知道哪个词已存在、是否已爬过。
3. **表格里的状态列存在感太弱**："最近获取"是一个 muted 灰色小字日期（`douyin-keywords.tsx:449-451`），"获取状态"徽标表达的是任务运行态而非"这个词的数据新鲜度"。用户扫一眼表格，无法快速区分"爬过且有数据 / 爬过但失败 / 从未爬过"。

### 1.3 密度问题：所有信息以同等权重平铺

逐页统计的密度证据（控件数为 Select/Input/TrackSelect 出现次数的保守估计）：

| 页面 | 行数 | 指标卡 | 筛选/输入控件 | 表格列+操作 |
|------|------|--------|--------------|-------------|
| 关键词管理 | 1107 | 5 | ~10（搜索/赛道/状态/启用/排序…） | 7 列 + 行内 4 个操作按钮 |
| 赛道管理 | 1284 | 4 | ~8 | 卡片 + 下拉菜单 + 工作区弹窗（500+ 行） |
| 评论管理 | 893 | 5 | 11 个筛选条件（可折叠面板） | 6 列 + 勾选 + 行内 3 操作 |
| 视频资源库 | 897 | 0 | 7 个筛选器 + 排序 | 卡片含 5 个互动数据 + 6 个操作图标 |
| 互动任务 | 742 | 配额卡网格 | 状态/类型/赛道 | 表格 + 行内 5 个操作 |
| 任务详情 | — | 4 | — | 进度卡+分片卡+作品面板(986 行)+互动面板+配置卡 |

用户在任一页面首屏看到的是：**4-5 张数字相近的指标卡 + 一排筛选器 + 一张塞满徽标和小字的表格**。所有元素字号、色重、密度接近，导致：

- **没有视觉锚点**：用户视线没有落点。"现在最需要我注意的"（失败的任务、等配额的互动、待扫码的登录）和"可以忽略的"（历史成功计数）以同样权重渲染。
- **指标卡通胀**：每页 4-5 张 MetricCard，数字本身没有解读（"62 个作品"是好是坏？），卡片占据首屏黄金位置却不驱动任何行动。
- **操作列拥挤**：资源库卡片单行 6 个图标按钮（预览/追爬/下载/重翻译/重试/沉浸播放），关键词行 4 个按钮并排，图标无语义分组，用户需要悬停逐个辨认。
- **徽标堆叠**：单行内状态徽标 + 赛道徽标 + 类型徽标 + 存储徽标并存，色彩多而不成体系，反而互相抵消了强调作用。

### 1.4 排版问题：信息组织按"数据表结构"而非"用户任务"组织

- 表格列是数据库字段的直译（ID/计数/时间戳平铺），而非按用户决策顺序组织（这个词要不要爬？→ 上次什么时候爬的？→ 出了多少数据？→ 要不要重爬？）。
- 空状态、错误、进行中、成功四种状态在同一个单元格区域混排，用户需要自己解析当前处于哪种。
- 详情页（任务详情）把进度、分片、作品、互动、配置五块纵向堆叠，滚动深度大，各块之间无导航锚点。

## 二、解决方案

### 方案总览：三刀切法

```text
第一刀：信息架构 —— 收敛为"一个发起入口 + 各域回归管理职责"
第二刀：状态前置 —— 把"已爬过没有"推到创建的那一刻
第三刀：视觉降噪 —— 每页只留一个视觉锚点，其余降级
```

### 方案一：信息架构收敛（解决"从哪开始"）

**核心动作：新增全局唯一的"开始采集"发起入口，四个现有入口全部指向同一套向导。**

1. 侧边栏"采集"分组顶部增加主按钮 **「+ 开始采集」**（视觉上唯一的主色实心按钮），点击打开统一的采集向导（Stepper 三步）：
   - **第一步：选赛道**（默认当前唯一/默认赛道，可折叠）
   - **第二步：选关键词**——从关键词库勾选（带状态：已爬过/未爬过/上次时间），同时允许临时输入新词（实时查重提示，见方案二）
   - **第三步：执行参数**（账号/风控档/媒体，复用现有 CreateTaskDialog 高级设置，默认收起）
2. 现有入口保留但降级为"快捷方式"：任务列表的创建按钮、赛道工作区、关键词批量建任务**全部复用同一个向导组件**，只是预填参数不同（赛道页预填赛道、关键词页预填勾选词）。
3. 三个入口提交后行为统一：**失效 `douyin-tasks` 查询 + toast 携带"查看任务"跳转链接**（修掉当前批量入口不闭环的 P1-2 问题）。
4. 赛道页减负：赛道卡片只保留"编辑/启停/删除/详情"，"运营这个赛道"改为跳向导并预填——`TrackWorkspaceDialog`（549-1073 行）整体被向导吸收，赛道页回归"管理赛道"单一职责。

**效果**：用户心智模型从"三个页面都可能发起"变成"一个入口发起，各页面管理各自的东西"。

### 方案二：状态前置（解决"这个词爬过没有"）

**核心动作：把关键词库的状态数据注入到每一个创建/输入的瞬间。**

1. **创建向导第二步：关键词选择器替代纯文本域**
   - 默认展示关键词库列表（可按赛道过滤），每行直接显示：`已爬过 · 1063 作品 · 3 天前` / `未爬过` / `进行中`，勾选即入任务。
   - 临时输入新词时**逐行实时查重**（防抖 300ms，复用现有关键词列表查询接口客户端过滤即可，无需新 API）：输入的词已存在时，行尾直接显示该词的状态徽标与"已存在 · 上次爬取 3 天前"，并询问"使用现有词还是新建副本"（默认使用现有词，避免重复词）。
2. **CreateKeywordsDialog 同样加实时查重**：输入框下方逐行回显"已存在/将新建"，提交前用户就知道结果，而不是提交后在 toast 里看"已存在 Y 个"。
3. **关键词表格"获取状态"列升级为"采集概览"列**：把现有的"获取状态徽标 + 关联任务计数 + 来源作品数 + 最近获取时间"四个分散单元格合并成一列结构化展示：
   ```text
   ✅ 已爬取 · 1,063 作品 · 最近 3 天前     （正常态）
   ⏳ 进行中 · 已完成 2/5 任务               （进行中）
   ⚠️ 上次失败 · 5 天前 · 查看错误           （异常态，链接到失败任务）
   ➖ 从未爬取                               （空态，行尾给"立即采集"快捷按钮）
   ```
   用户扫一眼即可按"数据新鲜度"排序决策，"立即采集"按钮直接带该词进向导第二步。
4. **排序默认值优化**：关键词列表默认排序改为"最近获取时间升序"（最久没爬的排最前），让"该重爬的词"自然浮上来，而不是默认按创建时间。

**效果**：用户在创建前、创建中、管理列表三个时刻都能看到"爬没爬过、什么时候爬的、出了多少数据"。

### 方案三：视觉降噪与层级规范（解决"密、杂、没重点"）

**核心动作：建立"每页一个视觉锚点"原则，其余信息按注意层级降级。**

1. **指标卡收敛**：
   - 每页指标卡 ≤4 张，且每张卡必须回答"我要不要行动"：只保留**需要行动的指标**（进行中任务数、失败数、今日配额剩余、待处理互动），纯统计量（历史作品总数、评论总数）降级为页面头部的次要文字或移入"概览"页。
   - 指标卡增加语义色：失败/异常用红、进行用蓝、正常用灰——当前全部同色系是"没有重点"的直接原因。
2. **筛选器分层**：
   - 高频筛选（搜索框 + 1-2 个主筛选）常驻；其余收入"更多筛选"折叠区（评论页 11 个筛选条件已在折叠面板里，方向正确，应推广到资源库的 7 个筛选器）。
   - 已激活的非默认筛选在折叠按钮上显示计数徽标（"更多筛选 · 3"），避免折叠后忘记自己筛过什么。
3. **操作列收敛**：行内操作按钮 ≤2 个（最高频：查看 + 一个主操作），其余收入行尾"⋯"菜单。资源库卡片的 6 个图标按此规则只留"预览 + 下载"，追爬/重翻译/重试/沉浸播放收进菜单。
4. **表格列减负**：每表 ≤6 列，低信息列（ID、创建时间）移除或并入详情。关键词表按方案二第 3 条合并四列为一列后，列数从 7 降到 5。
5. **视觉锚点规范**：每页定义一个"现在最该看的"区域并给视觉权重——任务列表页是"需要处理"筛选态下的异常行（整行浅红底而非仅徽标），互动页是待确认发送的行，任务详情页是进度卡。其余区域降灰。
6. **任务详情页加页内锚点导航**：进度 / 作品 / 互动 / 配置四个锚点，长页可直达。

### 落地顺序建议

| 批次 | 内容 | 改动面 | 前置依赖 |
|------|------|--------|----------|
| 第一批（纯前端，1-2 天） | 方案二第 3、4 条（关键词列合并 + 默认排序）+ 方案三第 3、4 条（操作列/表格列收敛） | 关键词页、资源库卡片 | 无 |
| 第二批（纯前端，2-3 天） | 方案二第 1、2 条（实时查重 + 关键词选择器雏形）+ 批量入口闭环修复（失效查询+跳转 toast） | CreateTaskDialog、CreateKeywordsDialog、两个批量入口 | 无（客户端过滤实现查重） |
| 第三批（组件级，3-5 天） | 方案一统一向导（Stepper + 四入口归一）+ 方案三第 1、5 条（指标卡收敛 + 视觉锚点） | 新增向导组件，赛道页减负，各页指标卡 | 第二批完成后 |

全部三批都不需要后端改动（查重、状态展示均复用现有关键词列表/任务列表接口）。

## 三、改前改后对比（以"创建关键词采集任务"为例）

**当前用户路径（6 步，含 2 个盲区）：**

```text
想到一个词 → 切到关键词页 → 翻列表/搜索确认有没有这个词（盲区①：也可能漏看）
→ 没有则先创建关键词（提交后才知道有没有重复）
→ 勾选 → 批量建任务 → 填参数提交
→ toast"成功"，不知道任务在哪（盲区②）→ 手动切任务页 → 等 3 秒轮询看到新任务
```

**改后用户路径（3 步，无盲区）：**

```text
点侧栏「+ 开始采集」→ 第二步输入/勾选关键词（已存在的词直接显示
"已爬过 · 3 天前 · 1063 作品"，新词实时提示"将新建"）
→ 提交 → toast"已创建，查看任务 →" 一键跳到任务详情
```

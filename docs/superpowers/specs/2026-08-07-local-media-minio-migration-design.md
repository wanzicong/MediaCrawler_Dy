# 本地视频迁移至 MinIO 设计

日期：2026-08-07
状态：已确认，待实施

## 1. 背景与目标

当前抖音媒体资产在下载时选择本地服务器或 MinIO，并通过
`DouyinMediaAsset.storage_backend`、`local_path`、`storage_bucket` 和
`object_key` 表示唯一生效的存储位置。预览、下载和字幕处理均根据这组字段自动读取本地文件或 MinIO 对象。

本需求为已经下载到本地服务器的视频增加单向迁移能力：用户可以针对整个抖音任务或指定视频，将现有本地文件上传到 MinIO。只有远端对象经过完整性校验后，系统才把资产的生效位置切换为 MinIO；数据库切换成功后删除本地文件。迁移完成后的数据形态应与“下载时直接选择 MinIO”一致，现有预览、下载和字幕功能无需使用第二套读取逻辑。

目标包括：

- 支持任务级批量迁移和指定资产迁移。
- 使用异步、可配置并发的后台处理，不阻塞 API 请求。
- 持久化每个资产的迁移状态、进度、重试次数、错误和时间。
- 对 MinIO 对象进行完整回读校验，确保大小和 SHA-256 均与本地源文件一致。
- 上传、校验或数据库切换失败时保留本地文件及本地存储状态。
- 数据库成功切换 MinIO 后删除本地文件，并对删除失败提供持久化恢复。
- 服务重启后自动恢复未完成的上传、切换或本地清理。
- 前端展示迁移进度、失败原因，并支持批量及单项重试。
- 提供与 FastAPI 等价的 MCP 工具，供外部 Agent 调用。

## 2. 非目标

- 不支持从 MinIO 迁回本地。
- 不重新从抖音下载视频；迁移只使用已经存在的本地成品。
- 不改变字幕正文的数据库存储方式。
- 不向 API、日志或迁移错误中暴露本地路径、MinIO 凭据、Cookie 或 Token。
- 不建立面向终端用户的 MinIO 永久直链；预览和下载继续经过现有鉴权接口。

## 3. 方案选择

采用独立、持久化的资产迁移状态机。

未采用以下方案：

- 重新下载到 MinIO：依赖可能已经失效的抖音地址或 Cookie，浪费外部带宽，也不等价于迁移本地成品。
- 复用下载状态：会混淆下载与存储迁移；迁移失败时本地文件仍可用，不能把资产错误地表现为下载失败。
- 独立批次表：当前迁移是每个资产仅执行一次的单向操作，批次历史不是业务目标。状态直接放在资产表上能以更少的模型和查询保持持久化、幂等与恢复能力。

## 4. 数据模型

为 `DouyinMediaAsset` 增加以下字段，并提供 Alembic 迁移：

- `migration_status`：字符串枚举，默认 `idle`，建立索引。
- `migration_progress`：0–100，默认 0。
- `migration_attempt_count`：默认 0。
- `migration_error`：可空文本，仅保存脱敏错误。
- `migration_started_at`：可空、带时区时间。
- `migration_finished_at`：可空、带时区时间。

迁移状态定义：

- `idle`：未迁移。
- `queued`：已进入后台队列。
- `uploading`：正在将本地文件上传至目标对象。
- `verifying`：正在从 MinIO 完整回读并校验。
- `switching`：完整性校验已通过，正在切换数据库存储位置。
- `cleanup_pending`：数据库已指向 MinIO，正在删除或等待重试删除本地文件。
- `completed`：数据库已指向 MinIO，且本地文件已经删除并清空 `local_path`。
- `failed`：上传、校验或切换失败；数据库和本地文件保持可用的本地状态。

下载状态 `status` 在迁移期间保持 `downloaded`，避免把迁移与下载混淆。字幕状态不受迁移影响。

成功切换数据库时暂时保留原 `local_path`，同时把 `storage_backend`、`storage_bucket` 和 `object_key` 切换为 MinIO，并把迁移状态设为 `cleanup_pending`。该路径只用于可靠地完成本地清理；预览和下载从切换提交后立即使用 MinIO。删除成功后清空 `local_path` 并将迁移状态设为 `completed`，此时资产的存储字段与直接下载至 MinIO 完全一致。

公共响应为 `DouyinMediaAssetPublic` 增加迁移状态、进度、尝试次数、脱敏错误和时间字段，但不返回 `local_path`、bucket、object key 或任何凭据。

媒体汇总响应增加：

- 已下载本地资产数。
- 已下载 MinIO 资产数。
- 等待迁移数。
- 迁移运行中数。
- 等待本地清理数。
- 迁移完成数。
- 迁移失败数。

## 5. 迁移工作流

### 5.1 资格检查

一个资产只有同时满足以下条件才允许开始上传：

- 属于当前用户有权访问的任务。
- 下载状态为 `downloaded`。
- 当前存储后端为 `local`。
- `local_path` 位于配置的媒体根目录下。
- 本地文件存在且大小大于 0。
- 当前没有其他进程已经成功认领该资产的迁移。

目标 bucket 使用当前 MinIO 配置；object key 复用
`MediaStorageService.object_key(task_id, aweme_id)`，与直接下载至 MinIO 的布局保持一致。

### 5.2 上传与完整性校验

每个资产按以下顺序执行：

1. 在数据库中原子认领资产，将状态改为 `uploading`，增加尝试次数并清除旧错误。
2. 读取本地文件大小并计算 SHA-256；已有 SHA-256 仍需在源文件变化时重新计算。
3. 创建 bucket（若不存在），以原 MIME 类型上传对象，并写入 SHA-256 元数据。
4. 将状态改为 `verifying`。
5. 调用 `stat_object` 校验远端对象存在且大小一致。
6. 使用 `get_object` 流式读取完整远端对象，在服务端重新计算 SHA-256。
7. 仅当远端大小和完整回读 SHA-256 均与本地文件一致时进入数据库切换。

MinIO 的上传成功响应、ETag 或由客户端写入的元数据不能单独作为完整成功的依据。完整回读会增加一次 MinIO 内网读取，但提供本需求要求的逐字节确认。

如果目标对象已经存在，仍必须执行大小和完整回读 SHA-256 校验。完全匹配时可跳过重复上传并继续切换；不匹配时覆盖上传后重新校验。

### 5.3 数据库切换与本地删除

完整性校验通过后：

1. 将状态设为 `switching`。
2. 在数据库事务中重新读取并锁定资产，确认它仍是相同的本地资产和相同源文件。
3. 原子写入 `storage_backend=minio`、目标 bucket、object key、校验后的大小和 SHA-256，并将状态设为 `cleanup_pending`；保留原 `local_path` 供清理恢复。
4. 只有事务提交成功后才尝试删除本地文件。
5. 删除成功后，在第二个短事务中清空 `local_path`，将进度设为 100、状态设为 `completed` 并记录完成时间。

数据库提交失败时不删除本地文件，资产仍保持本地存储状态。已上传但未被数据库引用的目标对象可以在确认本地文件仍可用后尽力删除；即使远端清理失败，也不得影响本地资产可用性。

本地删除因文件占用或瞬时 I/O 错误失败时，资产保持 MinIO 生效位置和 `cleanup_pending` 状态。系统保留内部 `local_path` 并自动重试删除；用户也可以手动重试。此时视频已经能够通过 MinIO 预览和下载，但迁移不显示为完全完成。

## 6. 并发、幂等与恢复

新增独立 `MediaMigrationManager`，避免影响现有视频下载和字幕并发。并发量通过 `MEDIA_MIGRATION_CONCURRENCY` 配置，默认 2。完整回读会占用 MinIO I/O，因此不复用字幕并发 5。

管理器按资产 ID 去重，并使用数据库条件更新或行锁完成跨请求认领。重复的批量请求遵循以下规则：

- 正在处理的资产不会重复排队。
- 已完成且本地文件已清理的 MinIO 资产直接跳过。
- 失败的本地资产可以重新排队。
- `cleanup_pending` 资产只重试本地删除，不重复上传。
- 本地资产对应的远端对象已完整匹配时，重试可以从数据库切换继续执行。

服务启动时执行恢复：

- `queued`、`uploading`、`verifying` 或本地后端的 `switching` 资产重新排队，并重新验证本地与远端内容。
- MinIO 后端的 `switching` 或 `cleanup_pending` 资产恢复本地删除，删除成功后完成状态收敛。
- 无法证明远端完整且本地文件不存在的异常状态标记失败并给出脱敏错误，不伪造成功。

服务关闭时等待正常取消；持久化状态由下次启动按上述规则恢复。

## 7. API 与 MCP

新增 FastAPI 接口：

`POST /api/v1/douyin/tasks/{task_id}/media/migrate-to-minio`

请求体：

- `asset_ids`：可选资产 ID 列表；空列表表示迁移任务下全部符合条件的本地视频。

返回 HTTP 202 和结构化结果，至少包含 `queued`、`skipped` 和提示信息。任务不存在或无权访问沿用现有 404/403。MinIO 未配置或预检不可用返回 503。指定资产不属于任务返回 404；指定资产不可迁移时返回明确的 409 或计入跳过结果，具体以保持批量接口可用为原则：批量请求允许部分排队，单项请求无可排队资产时返回 409。

现有媒体列表和汇总接口返回迁移进度。现有预览、文件下载、字幕处理接口保持路径和鉴权方式不变。

MCP 服务增加对应工具，例如 `migrate_douyin_media_to_minio`，参数与 API 保持一致。MCP 继续通过内部已鉴权 API 客户端调用，不直接操作数据库或 MinIO，不接受或返回 MinIO 凭据。

## 8. 前端交互

任务详情的“视频下载与字幕”面板增加：

- 顶部“上传本地视频到 MinIO”按钮，显示当前符合条件的本地视频数量。
- 确认对话框，明确说明系统会完整回读校验，只有成功后才切换并删除本地文件。
- 媒体表增加“存储迁移”状态与进度。
- 迁移失败资产显示脱敏错误和单项重试按钮。
- 存在失败项时提供批量重试。
- `cleanup_pending` 显示“MinIO 已生效，等待清理本地文件”，并提供重试清理。

只要存在迁移运行态，React Query 每 2 秒刷新媒体列表和汇总；全部收敛后停止额外轮询。批量接口对任务全部资产生效，不受前端当前仅展示第一页数据的限制。

## 9. 安全与可观测性

- API 继续使用任务所有者或超级管理员授权。
- 本地路径必须解析并验证位于 `MEDIA_OUTPUT_DIR`，禁止任意路径上传或删除。
- 所有错误通过现有安全错误处理脱敏，不记录 URL 查询参数、Token、Cookie、密钥和原始账号 ID。
- 日志只记录任务 ID、资产 ID、状态和脱敏错误，不记录本地绝对路径或 MinIO 凭据。
- 删除操作只针对数据库中已验证且位于媒体根目录的具体文件，禁止目录级递归删除。
- 本地删除前必须再次确认数据库已经提交为 MinIO，并确认远端对象大小和 SHA-256 已通过完整回读校验。

## 11. 交付判定

只有同时满足以下条件才视为需求完成：

- 批量和单项迁移、进度、失败重试、启动恢复均可用。
- 任何上传或校验失败场景都不会删除本地源文件。
- 只有远端完整回读校验和数据库切换均成功后才删除本地文件。
- 完成资产与直接下载至 MinIO 的存储字段形态一致。
- 迁移前后预览、下载和字幕功能保持可用。
- API、前端和 MCP 均可触发并观察迁移。
- 数据库迁移、静态检查、后端测试、前端测试、真实 MinIO 冒烟和 Docker 构建全部通过。

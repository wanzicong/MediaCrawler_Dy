一、闭环缺陷清单（按严重度分级）

P0用户会"以为自己没点上"或误操作的高危项

编号问题位置影响
P0-1 互动"确认发送"按钮无 loading、无确认、可重复点击。互动是真实发送到抖音的写操作（消耗账号配额、有风控后果），点击后没有任何进行态，网络慢时用户极可能连点，造成重复发送风险 douyin-interactions.tsx:401-408
TaskInteractionsPanel.tsx:166-173		 真实风控后果，最高优先级
P0-2 取消任务无二次确认。任务详情页"取消任务"是 destructive 按钮，点击即触发，无 Dialog、无 confirm。长时间运行的任务一次误点即终止 douyin_.$taskId.tsx:170-181 采集中断不可逆
P0-3 互动"取消"无确认、无 toast、无 loading——三重缺失：点击即请求，成功后仅靠轮询静默回显 douyin-interactions.tsx:421-429
TaskInteractionsPanel.tsx:193-201		 破坏性操作裸奔

二、各功能域闭环评分卡

评分维度：反馈及时性 / 防误操作 / 状态收敛 / 异常可见性（5 分制）

功能域评分评语

关键词管理★★★★★增删改移齐全、确认 Dialog 正式；启停静默 + 批量建任务断点同上

三、按用户角色的断点场景还原

场景 1：运营新人发出第一条评论回复 评论管理 → 找到目标评论 → 点"回复" → 两段式弹窗（选账号→写内容→发送前检查→确认发送）✅ 这段很好 → 到互动任务页 → 看到 needs_review → 点"确认发送"——按钮没有任何反应（P0-1）→ 不确定点没点上，再点一次 → 列表 2 秒轮询后状态才变 → 用户无法确认是点了两次还是一次。
场景 2：批量建 20 个关键词任务 关键词页勾选 20 条 → 批量建任务 → 配置 → 提交 → toast"成功" → 停留在关键词页（P1-2）→ 手动切到"抖音任务"——列表还是旧数据（查询未失效，要等 3 秒轮询）→ 用户困惑"任务到底建了没有"。
场景 3：想看某个视频的字幕（当前做不到） 任务详情 → 作品面板 → 字幕列显示"已完成" → 没有任何按钮能看字幕内容（P1-3）→ 只能点导出字幕文件下载到本地用记事本打开。字幕从"数据资产"变成了"只能导出不能读"的半成品。
场景 4：扫码登录卡在等待页 创建任务选扫码登录 → 二维码出现 → 用户去拿手机 → 回来二维码已换过两轮（15 秒/轮）→ 扫了旧码失败 → 页面没有任何"二维码已刷新，请扫最新码"的提示（P0-4）→ 用户反复扫旧码，直到任务超时失败。

四、优化路线图（按投入产出排序）

第一梯队：一行到几行代码，收益立竿见影
  1. 所有启停 toggle 补成功 toast（P1-1，3 处，每处 2 行）
  2. 批量建任务成功后失效 douyin-tasks 查询 + toast 带"查看任务"跳转（P1-2，2 处）
  3. 互动三操作（确认发送/重试/取消）接 isPending 禁用（P0-1/P1-5/P0-3 的 loading 部分，变量已存在只是没接线）
  4. 同步标签后 invalidate 查询（P2-6）
  5. 单条媒体操作图标接行级 pending（P1-4）
第二梯队：小组件级改造
  1. 统一 ConfirmDialog 组件替换 10 处 window.confirm（P2-1），并给取消任务、取消互动补上确认（P0-2/P0-3 的确认部分）
  2. 字幕查看弹窗：字幕列加按钮，复用 full_text 渲染逻辑（从死代码 MediaPipelinePanel 迁移），顺带删除两个未挂载遗留组件（P1-3）
  3. 二维码过期提示：TaskQrCode 增加"二维码每分钟刷新，请扫最新码"的预期管理文案与手动刷新按钮（P0-4）
第三梯队：需要产品决策
  1. 任务删除能力（P2-2）：需要后端定义级联策略（作品/评论/媒体是否同删），再进前端
  2. 账号登录弹窗拦截检测与页面内降级（P2-3）
  3. 清理 items 模板遗留切片（P2-4，前后端一起）

五、确认机制现状统计（一致性债务的证据）

确认方式数量用在哪
样式化 Dialog（符合设计语言）6 处删赛道、删关键词、移除关键词、恢复任务、迁移媒体、批量媒体处理
原生 window.confirm（突兀）10 处删账号、删账号池、批量删关键词、批量重试互动、单条重试互动、本地转云端、移动关键词×2 等
无任何确认（危险）3 处取消任务、取消互动、互动确认发送
核心结构性结论：同一种"破坏性操作"在系统里出现三种防护等级，且防护等级与真实风险成反比——发抖音评论（真实风控后果）无防护，删本地关键词（可重建）反而有正式 Dialog。这是最需要向团队传达的问题。
值得保留的亮点：互动创作弹窗的"发送前检查 → 草稿 → 确认发送"两段式是全系统最好的风控 UX 范本；赛道删除确认里写明"数据会完整迁移到默认赛道"是破坏性操作说明的范本；资源库筛选持久化到 URL 是可分享/可回退的高级做法。后续统一交互规范时应以这三处为基准向外推广。

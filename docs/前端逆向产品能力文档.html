0. 文档说明

0.1 编写目的

本文档以「逆向产品能力」为目标：不参考任何既有需求文档，纯粹从当前前端源码反向还原这套产品的交互、设计与模块能力，输出一份可以让产品/设计/研发三方对齐的"产品说明书"。每个页面均包含：页面用途、区块结构、交互元素、逐字 UI 文字草稿（含按钮、占位符、空态、错误态、Toast、校验提示）、业务规则与权限约束。

0.2 阅读约定

  • 文案均为源码逐字摘录，未做润色；{n}、{name} 等花括号表示运行期变量占位。
  • 「状态枚举」中的取值（如 queued、running）为前后端约定英文值，右侧中文为界面实际展示文案。
  • 「轮询」指前端 react-query 的自动刷新间隔。
  • 「线框」为 ASCII 文字版布局草稿，仅表达区块层级与位置，不表达像素尺寸。

0.3 产品一句话概述

灵感采集台是一个面向抖音内容运营的内部工作台：以「赛道」组织市场方向，以「关键词/任务」驱动抖音内容采集，沉淀视频、评论、标签三类内容资产，并通过托管账号池完成评论、回复、私信三类人工确认式互动，全程附带浏览器实时监控与风控配额管理。

1.3 角色与权限模型

角色 判定字段 能力边界
访客 无 access_token 仅可访问 4 个认证页
登录用户 isLoggedIn()（localStorage 存在 access_token） 全部业务页面；抖音各页无页面级角色门槛
超级管理员 user.is_superuser = true 额外可见/可访问「用户管理」；侧边栏该项仅对超管渲染

权限规则细节：

  1. 登录守卫：所有 _layout 下页面在路由 beforeLoad 中校验登录态，未登录一律重定向 /login。
  2. 认证页反向守卫：已登录用户访问登录/注册/找回/重置页一律重定向回 /。
  3. 重置密码前置：URL 无 token 查询参数时重定向到 /login。
  4. 资源级越权：不由前端路由拦截，统一由后端 403/404 表达，前端展示「{资源}不存在，或当前账号无权访问」。
  5. 敏感数据可见性：互动任务完整内容、操作截图「仅任务所有者可见」；账号平台标识不可逆脱敏；临时登录凭据仅内存使用、不落库、不写日志（均为界面文案承诺）。
  6. 自我操作限制：用户管理表格中当前登录管理员行不渲染操作菜单（不能在后台改/删自己）。

2.7 全局交互规则

  1. 登录守卫：无 token 访问任何业务页 → /login；token 失效由接口 401 触发登出。
  2. 确认对话框：破坏性操作（删除、批量迁移、批量重试等）一律 window.confirm 或确认 Dialog 二次确认，文案逐字见各章节。
  3. 自动刷新：进行中数据全部轮询（1s~15s 不等，完整汇总见第 9.8 节）；手动「刷新」按钮普遍存在于页头。
  4. 乐观反馈：所有写操作以 Toast「操作成功/操作失败」收尾；行级操作以 mutation.variables 精确禁用当前行按钮。
  5. 筛选即重置页码：所有列表页筛选变更自动回第 1 页。

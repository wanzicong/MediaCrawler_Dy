1. 产品概述

1.1 背景与问题

抖音内容运营团队日常工作存在四类断点：

  1. 采集散：按关键词/作品/创作者抓内容靠脚本和手工，任务状态不可见、失败无感知；
  2. 资产乱：抓回的视频、评论散落在本地文件夹，无法按市场方向（赛道）归集、筛选与复用；
  3. 互动险：评论、回复、私信等互动直接在账号上手工操作，无确认环节、无配额控制、无操作留痕，风控风险高；
  4. 环境杂：多账号共用浏览器指纹与登录态，易串号；远程浏览器状态不可见。

1.2 产品定位

灵感采集台是一站式抖音内容运营工作台：以「赛道」组织市场方向，以「关键词/任务」驱动内容采集，沉淀视频、评论、标签三类内容资产，并通过托管账号池完成人工确认式互动，全程附带浏览器实时监控与风控配额管理。

品牌主张（登录页品牌栏逐字）：把采集、管理与内容洞察，放进一个清爽的工作台。

1.3 产品目标

目标 衡量方式（现有能力支撑）
采集可追踪 任务 9 态状态机 + 四阶段进度 + 2~3 秒级实时刷新 + 断点续跑
资产可沉淀 视频资源库 / 评论管理 / 标签管理三视图，赛道自动归集
互动可管控 两段式人工确认 + 每日配额 + 最小间隔 + 24 小时防重 + 操作留痕
环境可隔离 每账号独立浏览器空间 + 远程槽位一对一绑定 + 账号池调度

1.5 名词术语表

术语 定义
赛道（Track） 市场方向的一级组织单元；关键词唯一归属一个赛道，任务与内容资产沿赛道归集
默认赛道 系统内置赛道，承接未指定归属的数据；不可删除、必须保持启用
关键词（Keyword） 采集搜索词，唯一归属一个赛道；有启停位与爬取状态
任务（CrawlTask） 一次采集作业（关键词搜索/指定作品/创作者作品/点赞/收藏），9 态状态机
分片（Shard） 使用账号池执行时按目标拆分出的子任务，每分片独立浏览器空间
媒体资产 任务作品对应的视频文件（本地服务器或云端 MinIO 存储）
字幕 由远程 Whisper API 生成的视频字幕，失败不回退本地模型
迁移（Migration） 本地视频上传云端的三步流程：上传 → 回读校验 → 切换存储后删本地
互动任务（Interaction） 视频评论/评论回复/作者私信，两段式人工确认后经托管浏览器执行
账号池（Account Pool） 托管抖音账号集合，支持并行调度策略（最少负载/顺序轮询/加权轮询）
槽位（Browser Slot） 一个远程常驻浏览器 + 持久化登录空间，一对一绑定账号
待人工核对（needs_review） 互动执行结果不确定，需人工到抖音确认未发送后再重试

2. 用户、角色与核心场景

2.1 角色定义

角色 判定 能力边界
访客 无登录态 仅 4 个认证页
内容运营（登录用户） 有效 access_token 全部业务页面（抖音各页无页面级角色门槛）
超级管理员 is_superuser = true 额外可见/访问「用户管理」

权限细则：未登录访问业务页一律重定向 /login；已登录访问认证页重定向 /；重置密码页必须带 token；资源级越权由后端 403/404 表达，前端提示「{资源}不存在，或当前账号无权访问」；管理员无法在后台编辑/删除自己（行内不渲染操作菜单）。

2.2 核心场景故事线

场景 A：开辟一个新市场方向并采集内容（P0 主链路）

  1. 运营在「赛道管理」创建赛道「户外露营装备」，写入目标人群与初始关键词；
  2. 在赛道运营工作区勾选本次采集关键词，选择「组合任务」与执行账号，启动采集；
  3. 若任务进入「等待扫码」，在任务详情页用抖音 App 扫码，任务自动继续；
  4. 在任务详情页观察四阶段进度（作品采集 → 评论采集 → 视频下载 → 字幕处理），异常时一键「继续任务」断点续跑；
  5. 采集完成后，作品自动沉淀到「视频资源库」，评论进入「评论管理」，话题自动抽取为「标签」。

场景 B：基于评论洞察发起互动（P0 风控链路）

  1. 运营在「评论管理」按赛道+关键词+点赞区间筛出高价值评论；
  2. 点击行内「回复」，选择发送账号（可见今日剩余配额与最小间隔），撰写内容；
  3. 系统先「发送前检查」生成草稿，运营「确认并发送」后进入浏览器执行队列；
  4. 在「实时监控」抽屉观察浏览器画面与执行链路（每秒刷新），平台确认接收后任务「已成功」；
  5. 若结果不确定进入「待人工核对」，运营先到抖音确认未发送，再执行重试，避免重复发送。

场景 C：多账号并行与风险控制（P0）

  1. 管理员在「账号池」添加托管账号（别名即可，无需抖音号），远程槽位自动分配；
  2. 打开账号专属浏览器完成扫码登录，回到页面「验证」后进入可用池；
  3. 创建并行账号池（如 5 账号、最少负载策略、最大并行 3）；
  4. 批量关键词任务按目标拆分分片并行执行，每账号受每日任务上限与配额约束；
  5. 「浏览器监控中心」5 秒级探测每个槽位健康度与活动页面，可直接 iframe 内人工接管。

场景 D：资产云端化与沉浸复盘（P1）

  1. 资源库筛选某赛道「本地服务器」视频，一键「本地视频转云端」（确认框明示三步安全流程）；
  2. 迁移完成后用「沉浸播放」全屏竖滑复盘内容，支持 J/K 与滚轮切换；
  3. 选中作品导出评论 TXT 或字幕 SRT/VTT/TXT，供内容分析。

3.4 全局交互规范

  1. 反馈：写操作一律以 Toast 收尾，成功标题「操作成功」、失败标题「操作失败」；行级操作仅禁用当前行按钮（mutation.variables 级 pending）。
  2. 确认：破坏性操作（删除/批量迁移/批量重试等）必须二次确认（confirm 或确认 Dialog），确认文案须明示后果与不可逆性。
  3. 实时性：进行中数据按第 8.2 节轮询表自动刷新；页头普遍提供手动「刷新」。
  4. 筛选：筛选变更即重置页码；列表页空态/加载态/错误态三态齐全，错误态统一使用 QueryErrorState（标题 + 描述 +「重试/正在重试…」按钮）。
  5. 异常兜底：未匹配路由 → 404 页（「页面不存在」）；路由渲染异常 → 异常页（「暂时无法打开这个页面」）；两者均提供「返回工作台」。
  6. 错误文案：后端英文错误码经中文化映射表转换后弹出（含登录失效、账号停用、密码错误、邮箱已注册等 12 条映射 + 网络错误与兜底文案）；未命中映射的原文弹出。

4. 功能需求详述

4.1 认证模块

FR-AUTH-01 登录（P0）

  • 页面：/login，标题「欢迎回来」，副标「登录后继续管理你的采集任务与内容资产」。
  • 交互：邮箱 + 密码 +「登录」；「忘记密码？」→ /recover-password；底部「还没有账号？ 立即注册」→ /signup。
  • 校验：请输入有效的邮箱地址 / 请输入密码 / 密码至少需要 8 个字符（onBlur 触发）。
  • 规则：成功写 token 进首页；后端错误映射为中文 Toast（邮箱或密码错误 / 账号已停用等）。
  • 验收：正确凭据跳转 /；错误凭据出现对应中文 Toast；已登录访问本页重定向 /。

FR-AUTH-02 注册（P0）

  • 页面：/signup，标题「创建账号」，副标「加入灵感采集台，开始管理你的内容工作流」。
  • 字段：姓名 / 邮箱 / 密码（占位「至少 8 个字符」）/ 确认密码；按钮「注册」；底部「已有账号？ 返回登录」。
  • 校验：含「两次输入的密码不一致」（挂在确认密码字段）。
  • 规则：提交时剔除确认密码；邮箱重复 → Toast「该邮箱已注册，请直接登录」。
  • 验收：合法注册成功；重复邮箱提示明确；二次密码不一致被拦截。

FR-AUTH-03 找回密码（P1）

  • 页面：/recover-password，标题「找回密码」，副标「输入注册邮箱，我们会发送密码重置链接」。
  • 交互：邮箱 +「发送重置邮件」；成功 Toast「密码重置邮件已发送，请检查收件箱」并重置表单。

FR-AUTH-04 重置密码（P1）

  • 页面：/reset-password，标题「重置密码」，副标「设置一个至少 8 位的新密码」。
  • 前置：URL 无 token 重定向 /login。
  • 字段：新密码 / 确认新密码；按钮「更新密码」。
  • 规则：成功 Toast「密码已更新，请重新登录」并跳 /login；token 失效提示「链接已失效，请重新操作」。

4.2 概览域：工作台

FR-DASH-01 运营总览（P0）

  • 页面：/，eyebrow「今日运营概览」，标题「你好，{姓名}」（无姓名「欢迎回来」）。
  • 区块：状态胶囊×3（进行中任务/需关注/可用账号）→ 指标卡×4（任务总数/{范围}作品/{范围}评论/可用账号）→ 异常横幅（条件出现）→ 最近任务（前 6 条，双列卡片）。
  • 关键文案：描述「从任务调度、账号可用性到内容沉淀，一眼掌握当前运营状态；需要处理的异常会优先浮到前面。」；横幅「有 {n} 项任务需要处理 ｜ 包括等待扫码、失败或中断的任务，建议优先检查。」；空态「暂无任务，前往任务中心创建第一个任务。」
  • 规则：任务 5 秒轮询；「需关注」= failed/interrupted/waiting_login；数据范围标签按是否截断显示「近 100 个任务/全部任务」；账号/任务读取失败分别出错误块。
  • 验收：各计数与接口一致；横幅仅在需关注 >0 时出现；点击任务卡进详情。

4.3 采集域

FR-TRACK-01 赛道列表与生命周期（P0）

  • 页面：/douyin-tracks，eyebrow「私域增长」，标题「赛道管理」。
  • 区块：指标卡×4（运营赛道/关键词资产/赛道作品/目标评论）→ 搜索 → 赛道卡片网格（md:2/xl:3 列）。

  • needs_review Alert：标题「需要人工检查」，描述「请先打开抖音确认内容没有发送成功，再执行重试，以免重复发送。」
  • 验收：截图加载/失败两态文案正确；事件行内显示「第 {n} 次执行」。

FR-INT-04 实时监控抽屉（P0）

  • 抽屉：InteractionLiveMonitor（右侧 Sheet），标题「评论实时监控」，描述「实时观察账号浏览器和执行链路；关闭监控不会中断评论任务。」
  • 能力：嵌入浏览器实时画面（云端槽位；本机浏览器显示「暂无可嵌入的实时浏览器」及说明）、延迟徽标「{n} ms」、执行链路每秒刷新（空态「正在等待任务进入执行队列…」）、按钮「打开抖音原视频/新窗口监控/刷新」。
  • 规则：详情 1 秒、槽位 2 秒轮询（仅打开时）；无障碍 live 文本播报最新步骤。

FR-ACCT-01 托管账号管理（P0）

  • 页面：/douyin-accounts，eyebrow「账号与浏览器身份」，标题「抖音账号池」。
  • 区块：指标卡×4（托管账号/当前可用/执行中/远程槽位可用）→ 远程浏览器槽位卡 → 账号表格 → 账号池卡片网格。
  • 添加账号：别名（必填，「不需要填写抖音号」）+ 浏览器位置（云端托管/本机专属）；远程模式自动分配第一个可用槽位（「留在“自动分配”即可…」）；无槽位错误提示三种解法。
  • 账号生命周期：登录（有 viewer 新窗口打开，Toast 提示允许弹窗）→ 验证（Toast「登录验证成功，账号已进入可用池」）→ 停用/启用 → 删除（confirm「确认删除账号“{name}”及其专属浏览器空间？」）。
  • 规则：执行中（active_leases>0）禁止登录/验证/启停/删除；列表/槽位 5 秒轮询、retry: false；隐私承诺「平台账号标识经过不可逆脱敏，敏感登录信息不会在内容数据、操作日志或页面中暴露。」
  • 验收：账号 7 态徽标文案正确（待登录/待验证/可用/执行中/冷却中/异常/已停用）。

FR-ACCT-02 并行账号池（P0）

  • 创建对话框：账号池名称 + 加入账号（复选，含状态）+ 调度策略（最少负载/顺序轮询/加权轮询）+ 最大并行账号（1–20，夹在已选数内）。
  • 规则：任务按目标拆分分片、独立浏览器空间并行执行；删除池不影响账号与登录状态（Toast「账号池已删除，账号与登录状态不受影响」）。

FR-BR-01 浏览器监控中心（P1）

  • 页面：/douyin-browsers，eyebrow「浏览器实时运营」。
  • 区块：指标卡×4（常驻浏览器/连接状态 {healthy}/{total}/已绑定账号/活动页面）→ 左槽位列表 + 右实时画面（iframe）→ 底部当前活动页面。
  • 规则：5 秒轮询、retry: false；默认选中第一个槽位，失效回落；iframe allow 剪贴板与全屏；无 viewer 时显示「该槽位暂未提供实时操作画面 ｜ 浏览器连接状态仍会持续监控。」
  • 验收：健康点绿/红与「浏览器在线/离线」徽标一致；「新窗口操作」「打开页面」外链正确。

4.6 系统域

FR-DEV-01 开发者中心（P1）

  • 页面：/developer-tools，eyebrow「API 与 MCP 集成目录」；数据 staleTime 30 秒。
  • 能力：API 文档标签页（方法徽标/路径/summary/鉴权徽标/请求参数/请求体/响应码，分组筛选 + 搜索）+ MCP 工具标签页（STDIO 与 Streamable HTTP 接入卡、端点复制、工具参数明细）+ 内嵌 Swagger 对话框（「调用受保护接口前请在文档中完成 Authorize。」）。
  • 规则：文档完全由运行时 OpenAPI/MCP 注册表生成，无需手工维护；错误态「文档加载失败 ｜ 无法从后端读取集成目录，请确认 API 服务已启动。」+「重新加载」。

FR-ADMIN-01 用户管理（P0，仅超管）

  • 页面：/admin，eyebrow「系统权限」；路由级超管守卫。
  • 能力：用户列表（Full Name/Email/Role/Status/Actions，一次拉取 100 条前端分页）、新增、编辑（密码留空即不修改）、删除（级联删除其全部条目，确认文案明示）。
  • 规则：当前登录管理员行无操作菜单（不能改/删自己）；角色徽标 Superuser/User；状态 Active/Inactive。
  • 已知缺口：模块内部文案全英文未中文化，见 10.1 #4。

FR-SET-01 个人设置（P1）

  • 页面：/settings，eyebrow「账号与安全」；三标签页。
  • 个人资料：姓名/邮箱查看-编辑切换；仅提交变更字段；保存仅 dirty 可用；姓名 ≤30 字（校验提示缺中文，见 10.1 #8）；成功 Toast「个人资料已更新」。
  • 登录密码：当前/新/确认三框；新密码 ≠ 当前密码（后端校验前端翻译）；成功 Toast「密码已更新」。
  • 危险操作：删除账号（红色卡 + 确认对话框「账号与全部关联数据将被永久删除。此操作无法撤销，请确认后继续。」）；成功后登出。
  • 已知问题：超管同样可见危险操作（疑似应隐藏的 no-op 逻辑），见 10.1 #2。

5. 状态机与核心业务规则

5.1 采集任务状态机（9 态）

queued 排队中 / waiting_login 等待扫码 / running 运行中 / processing_media 处理视频/字幕 / cancelling 取消中 → 活跃；succeeded 已完成 / failed 失败 / cancelled 已取消 / interrupted 已中断 → 终态。

  • 活跃 → 可「取消任务」，详情/分片 2 秒轮询；
  • 终态 → 可「继续任务」（断点续跑，分「继续爬取」与「继续视频下载和字幕」两独立范围，记录 resume_count / last_resumed_at / checkpoint_phase）；
  • failed/interrupted/waiting_login 计入列表「需处理」与工作台「需关注」；
  • waiting_login 触发二维码卡片（15 秒刷新，扫码成功自动继续）。

5.2 关键词状态（4 态 + 启停位）

unprocessed 未爬取 / active 进行中 / crawled 已爬取 / failed 需要重试（赛道详情页写作「需重试」，见 10.1 #13）；停用优先显示「已停用」。唯一归属一个赛道；删除/移动不删历史任务与内容。

5.3 媒体下载 / 字幕 / 迁移状态机

域 流转 界面文案
下载 queued → downloading → downloaded / failed 等待中 / 下载中 / 已下载 / 失败
字幕 pending → running → completed / failed 等待字幕 / 字幕处理中 / 字幕完成 / 失败
迁移 idle → queued → uploading → verifying → switching → cleanup_pending → completed / failed 无需迁移·未迁移 / 等待上传 / 上传中 / 完整性校验中 / 切换存储中 / 云端存储已生效，等待清理本地文件 / 迁移完成 / 迁移失败
  • 迁移安全承诺（产品红线）：完整回读校验通过后才删除本地文件；任何一步失败本地保留、可稍后重试。
  • 字幕由远程 Whisper API 生成，失败记录错误、不回退本地模型。
  • 重试 = 下载 + 字幕同时重排队；重新翻译 = 单独重提字幕。

5.4 互动任务状态机（8 态）

pending_confirmation 待确认 → 人工确认 → queued 排队中 → running 发送中 → succeeded 已成功 / failed 失败 / blocked 已暂停 / needs_review 待人工核对 / cancelled 已取消。

  • 两段式人工确认（发送前检查 → 草稿 → 确认发送）为产品级风控红线；
  • needs_review 必须先人工确认「未发送」再重试（防重复发送）；
  • 同目标+同内容 24 小时内拦截；
  • 内容加密保存、不写日志；完整内容与截图仅任务所有者可见。

5.5 账号与槽位

  • 账号 7 态：待登录 / 待验证 / 可用 / 执行中 / 冷却中 / 异常 / 已停用；
  • 槽位：配置异常 / 可用 / 已占用，一对一绑定账号；
  • 调度策略：最少负载 / 顺序轮询 / 加权轮询；最大并行 1–20；
  • 执行中（active_leases>0）禁止登录/验证/启停/删除。

5.6 赛道规则

  • 默认赛道不可删除、必须保持启用；
  • 删除赛道 → 关键词/任务/内容完整迁移到默认赛道；
  • 停用赛道不可启动采集；工作区固定云端浏览器 + 云端存储 + 稳档风控。

7. 非功能需求

7.1 性能与实时性

  • 自动刷新分级：实时监控 1 秒级；执行中任务/互动 2 秒级；列表概览 3–5 秒级；元数据 10–30 秒级（staleTime）；全量轮询表见 7.2。
  • 列表大数据量采用服务端分页 + placeholderData 保留上一页，翻页无闪空。
  • 视频播放按需分段读取（preview-session + range），关闭播放器即停止读取。

7.2 轮询策略一览

位置 间隔 位置 间隔
互动实时监控详情 1 秒 互动任务列表/面板 2 秒（有进行中）/ 5 秒
任务详情/分片（活跃） 2 秒 工作台任务 5 秒
统一工作区（活跃/非活跃） 2 / 5 秒 视频资源库 5 秒
任务列表 3 秒 账号池/槽位/浏览器监控 5 秒
作品评论弹窗（open+活跃） 3 秒 关键词列表/概览 5 / 10 秒
执行进度媒体汇总 2 / 10 秒 赛道列表/详情 10 秒
互动配额 5 秒 评论管理 不轮询（手动刷新）

7.3 安全与隐私

  • 全站登录守卫（localStorage token），认证页反向守卫，401 触发登出；
  • 受保护媒体/导出/截图接口携带 Authorization: Bearer {token}，预览另建短时会话（数分钟失效）；
  • 临时登录凭据仅内存使用、不落库、不写日志，任务受理后自动清除（UI 明示）；
  • 互动内容加密保存、不写入应用日志；账号平台标识不可逆脱敏；
  • 互动完整内容与操作截图仅任务所有者可见；
  • 任务配置卡默认收起且敏感登录信息不展示。

7.4 可用性与无障碍

  • 全站「跳到主要内容」链接；图标按钮 aria-label；实时监控含无障碍 live 播报；
  • 支持 prefers-reduced-motion；明暗模式跟随系统；
  • 表单校验 onBlur/onSubmit 分级，错误信息中文（已知缺口见 10.1）。

7.5 兼容性

  • 桌面优先（最大内容宽 1600px），移动端断点 md 表格降级为卡片；
  • 沉浸播放支持触摸滑动与键盘（↑↓/J/K/PageUp/PageDown）。

8. 埋点与度量（现状说明）

当前版本以前端轮询与状态外显为运营度量手段（指标卡、需处理角标、配额卡），未接入独立埋点系统。后续迭代如需转化漏斗与功能使用率度量，建议基于第 4 章需求编号建立事件字典。

9. 边界与不做的事（Non-Goals）

边界 说明

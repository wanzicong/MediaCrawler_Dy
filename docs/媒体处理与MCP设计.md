# 媒体处理与 MCP 设计

## 目标

在不阻塞抖音爬取的前提下下载视频、调用远程 Whisper API 生成字幕，并让 Web、
REST API 和外部 Agent 都能看到同一份进度和结果。

## 处理策略

`CrawlTaskCreate.media_processing_mode` 支持：

- `none`：不处理媒体。
- `immediate`：作品落库后立即创建独立媒体任务，下载/字幕与后续爬取并行。
- `batch`：爬取完成后一次性创建全部媒体任务。

爬取结束后主任务进入 `processing_media`，等待本任务已经排队的媒体作业收敛，再进入
`succeeded`。单个媒体失败不会丢失已抓取数据，失败项可以独立重试。

任务提交后先显示 `queued`，后台真正开始创建媒体记录时再进入 `processing_media`。
CDP 并发限制只包围浏览器爬取阶段；浏览器关闭并释放槽位后才等待批量媒体收敛。
下载和字幕分别使用跨任务公平限流，后提交的小任务不会排在一个大任务的全部作品之后。

`CrawlTaskCreate.media_storage` 支持 `local` 和 `minio`。字段省略时由服务级
`MEDIA_STORAGE_BACKEND` 决定；解析后的值写入任务公开参数，之后的下载与重试都使用
同一后端，不会因服务配置变化而切换存储。

## 中断恢复

`crawl_task.checkpoint_json` 保存版本化内部断点，只包含任务阶段、页码/游标、目标索引和
待补作品 ID，不包含 Cookie、Token、原始账号 ID 或浏览器状态。恢复仍使用原任务 ID，
依靠作品、评论、互动和媒体表的唯一约束保证幂等。

- `crawl`：继续关键词页码、指定作品索引、创作者游标或个人 feed 游标；中断页评论会
  重新读取并 upsert。
- `media`：爬取已经完成，只需扫描全部作品补建媒体资产、下载和字幕。
- `completed`：抓取和媒体编排已经完成；仍允许再次扫描媒体，用于恢复单项失败。

服务启动时仍先把残留活动状态标记为 `interrupted`/`failed`，不会未经用户确认自动控制
CDP 浏览器。用户通过 Web、REST 或 MCP 恢复；恢复次数和时间写入任务审计字段。
Cookie 登录任务恢复时可提交一次性 Cookie，否则改用持久化 CDP 登录态或二维码。

## 作品级后续任务

任务详情页以视频为入口展示已保存评论，并支持创建两类独立后续任务：

- 评论重爬：`detail` 任务只处理选中的作品，评论数量、子评论、并发和 CDP 模式独立配置。
- 作者作品：`creator_from_aweme` 任务先请求作品详情，在内存中取得作者 `sec_uid`，然后
  复用创作者分页与断点逻辑抓取作品；原始 `sec_uid` 不写入请求配置、断点或数据表。

后续操作不改写来源任务状态和历史结果。新任务拥有自己的取消、失败、恢复、媒体后处理
和评论分页；Web 创建成功后进入新任务，REST 和 MCP 返回完整任务对象。

## 数据模型

- `douyin_media_asset`：一条任务作品对应一个媒体资产，保存下载状态、百分比、文件摘要、
  存储后端、bucket、对象键、尝试次数和错误。源地址、本地路径、bucket 与对象键不通过
  API 返回，公开模型只返回 `storage_backend`。
- `douyin_subtitle`：一个媒体资产对应一条当前字幕结果，保存请求/实际后端、模型、语言、
  百分比、字幕正文、时间分段、尝试次数和错误。

强制重新翻译会增加尝试次数并原子覆盖当前字幕正文；下载文件不重复下载。失败重试仅
重置选中的失败步骤。

## 完成后媒体处理

爬取时未启用媒体的任务，在爬取阶段完成且已有作品后，可以通过 Web、REST
`POST /tasks/{id}/media/process` 或 MCP `process_douyin_task_media` 启动批量后处理，
无需重新打开 CDP 浏览器或重新爬取。

- 视频下载始终启用，可选择 `local`、`minio` 或服务默认存储；未下载/失败资源采用本次选择，已有文件不迁移。
- 可选择只补缺失/失败字幕，或强制重新生成已经完成的字幕。
- 翻译仍只调用远程 Whisper API；视频未下载时会先下载再翻译。
- 一次性 Cookie 只进入当前内存任务的下载请求头，不写入任务配置、数据库或响应。
- 处理配置会成为任务当前有效媒体配置；服务中断后可通过原有媒体断点继续。

## 存储流程

- 下载统一写入 `MEDIA_OUTPUT_DIR/.staging`，完成大小与 SHA-256 校验后再提交存储。
- `local` 使用同文件系统原子移动，Docker 中目录固定在持久化 `crawler-data` 卷。
- `minio` 上传到私有 bucket 后删除暂存文件；字幕处理时按需下载到临时目录，结束后
  自动清理，不会保留第二份视频。
- MinIO SDK 支持服务端配置的远程 MinIO/S3 兼容地址。请求只能选择后端类型，不能传入
  endpoint、bucket 或密钥。
- MinIO 不可用、鉴权失败或上传失败时媒体任务进入 `failed`，绝不回退到本地。

## 安全边界

- 抖音 Cookie 仅在媒体任务闭包中短暂使用，不写入数据库或日志。
- Whisper API Key 使用 Pydantic `SecretStr` 从环境变量读取。
- 不安装或调用本地 Whisper 模型。远程连接、鉴权、超时、非 2xx 响应或响应格式错误
  都会把字幕任务直接标记为 `failed`，错误经过脱敏后保存，用户可以重试。
- FFmpeg 只负责把视频提取为 16 kHz 单声道压缩音频，随后仍只调用远程 Whisper API；
  这一步用于缩小上传体积，不构成本地识别或远程失败后的本地回退。
- 非回环 HTTP Whisper 地址被拒绝，远程服务必须使用 HTTPS。
- 视频文件只能通过任务所有权校验后的 API 下载，响应不暴露服务器本地路径。
- MinIO bucket 保持私有；文件接口由后端鉴权后流式代理对象，不向前端泄露内部 endpoint
  或签名 URL。
- 下载限制响应类型、文件大小、超时和重试次数，并通过 `.part` 文件原子提交。

## MCP

MCP 进程不直接访问爬虫任务管理器，而是登录 FastAPI 后调用 REST API，因此：

- Web、REST 和 Agent 共用权限、状态和数据。
- MCP 重启不会把运行中的 FastAPI 任务标记为中断。
- MCP 进程不持有抖音 Cookie，也不直接读取视频文件。
- Agent 可创建、查询、取消任务，分页读取作品/评论/匿名互动，按视频重爬评论或抓取
  作者作品，以及查询、重试和重新翻译媒体任务。

网络 MCP 默认只绑定本机。任何能够调用 MCP 的客户端都能使用配置的服务账号权限，
如需暴露到其他机器，应在反向代理增加 TLS、身份认证和访问控制。

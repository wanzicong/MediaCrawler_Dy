# 媒体处理与 MCP 设计

## 目标

在不阻塞抖音爬取的前提下下载视频、调用远程 Whisper API 生成字幕，并让 Web、
REST API 和外部 Agent 都能看到同一份进度和结果。

## 处理策略

`CrawlTaskCreate.media_processing_mode` 支持：

- `none`：不处理媒体。
- `immediate`：作品落库后立即创建独立媒体任务，下载/字幕与后续爬取并行。
- `batch`：爬取完成后一次性创建全部媒体任务。

爬取结束后主任务进入 `processing_media`，等待本任务已经排队的媒体作业收敛，再进入
`succeeded`。单个媒体失败不会丢失已抓取数据，失败项可以独立重试。

## 数据模型

- `douyin_media_asset`：一条任务作品对应一个媒体资产，保存下载状态、百分比、文件摘要、
  尝试次数和错误。源地址与本地路径不通过 API 返回。
- `douyin_subtitle`：一个媒体资产对应一条当前字幕结果，保存请求/实际后端、模型、语言、
  百分比、字幕正文、时间分段、尝试次数和错误。

强制重新翻译会增加尝试次数并原子覆盖当前字幕正文；下载文件不重复下载。失败重试仅
重置选中的失败步骤。

## 安全边界

- 抖音 Cookie 仅在媒体任务闭包中短暂使用，不写入数据库或日志。
- Whisper API Key 使用 Pydantic `SecretStr` 从环境变量读取。
- 不安装或调用本地 Whisper 模型。远程连接、鉴权、超时、非 2xx 响应或响应格式错误
  都会把字幕任务直接标记为 `failed`，错误经过脱敏后保存，用户可以重试。
- 非回环 HTTP Whisper 地址被拒绝，远程服务必须使用 HTTPS。
- 视频文件只能通过任务所有权校验后的 API 下载，响应不暴露服务器本地路径。
- 下载限制响应类型、文件大小、超时和重试次数，并通过 `.part` 文件原子提交。

## MCP

MCP 进程不直接访问爬虫任务管理器，而是登录 FastAPI 后调用 REST API，因此：

- Web、REST 和 Agent 共用权限、状态和数据。
- MCP 重启不会把运行中的 FastAPI 任务标记为中断。
- MCP 进程不持有抖音 Cookie，也不直接读取视频文件。
- Agent 可创建、查询、取消任务，分页读取作品/评论/匿名互动，以及查询、重试和
  重新翻译媒体任务。

网络 MCP 默认只绑定本机。任何能够调用 MCP 的客户端都能使用配置的服务账号权限，
如需暴露到其他机器，应在反向代理增加 TLS、身份认证和访问控制。
